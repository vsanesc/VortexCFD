## Task 6.1 Part A: stopping criteria (decisions taken while Vic was away)

60. **[DECIDED (review chat 2026-10-17): over the last W iterations (max - min) / max(|mean|, floor) <= tol (default 1e-3, floor 0.01 for coefficients, user-set for probes), evaluated by the app, which then stops the solver with the clean stop; runTimeControl only for residual-only criteria (D-058, Accepted).]** **Asymptotic tolerance is absolute, not relative.** The task asked for "relative change of the windowed average, as in a range-based asymptotic criterion". The stop must be OpenFOAM's runTimeControl, and v2606's `average` condition only offers |x_n - mean of last W| <= tolerance with an absolute tolerance (src/OpenFOAM/db/functionObjects/valueAverageBase/valueAverageBaseTemplates.C). I implemented exactly that (D-058), tolerance in the quantity's units (default 1e-4). It is weak: on the coarse sphere, window 20 and tolerance 1e-3 stopped at iteration 49 because Cd happened to cross its window mean, while Cd still moves by several per cent afterwards. As far as I know (not checked against a manual: no access offline) the usual commercial asymptotic criterion is max - min over the last N samples below a limit. Options: (a) keep it, with larger windows and tighter tolerances by default; (b) chain a `valueAverage` function object (windowed mean of Cd) and put the `average` condition on that mean, which tests the drift of the windowed average (closer to the request, still absolute); (c) a relative tolerance by rewriting the controlDict during the run (runTimeModifiable), fragile; (d) a `coded` function object implementing max - min (compiles at run time). [NUMERICS-REVIEW]
