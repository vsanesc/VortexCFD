# DECISIONS.md

| ID | Date | Decision | Reason |
|---|---|---|---|
| D-001 | 2026-10-15 | OpenFOAM ESI v2606 only | Avoids supporting multiple OpenFOAM forks and version differences during development. |
| D-002 | 2026-10-15 | Run inside WSL + WSLg | Eliminates cross-OS filesystem translation overhead while providing Linux solver execution and hardware-accelerated rendering on Windows. |
| D-003 | 2026-10-15 | Three-layer package structure | Decouples simulation logic from the UI to allow headless execution and testing without Qt dependencies. |
| D-004 | 2026-10-15 | OpenFOAM always launched via explicit sourcing | Ensures deterministic execution regardless of the user's host shell environment or PATH configuration. |
| D-005 | 2026-10-15 | Results stored as standard OpenFOAM cases | Allows cases to be opened directly in ParaView without relying on an application-specific format. |
| D-006 | 2026-10-15 | Project file format: JSON, validated with pydantic, with schema_version | Provides human-readable versioned project files with schema validation and migration support. |
| D-007 | 2026-10-15 | Project license GPL-3.0-or-later | Required because the foamlib runtime dependency is licensed under GPLv3. |
| D-008 | 2026-10-15 | Use foamlib for reading/writing OpenFOAM files, isolated behind foam/dictfile.py | Encapsulates the third-party OpenFOAM parser and serializer behind a single internal interface. |
| D-009 | 2026-10-15 | Clean stop via controlDict stopAt writeNow | Enables solver to write the current time step and exit cleanly without corrupting state. |
| D-010 | 2026-10-15 | Clean stop via SIGUSR1 with stopAtWriteNowSignal in case controlDict (supersedes D-009) | Measurements showed file-based stop is delayed ~5 s by fileModificationSkew, while SIGUSR1 stops cleanly in ~0.01 s without mutating case files on disk. |
| D-011 | 2026-10-15 | Undo/redo as snapshots in core/project.py instead of QUndoStack | Snapshots of the validated Simulation work headless and from scripts, while QUndoStack would tie the document to Qt. |
| D-012 | 2026-10-15 | Project renamed to VortexCFD (Python package vortexcfd) | Final name chosen before the GUI and public API grow. |
| D-013 | 2026-10-16 | GUI look: design tokens in gui/theme.py, Fusion style, icons drawn in code, no bundled assets | One place to change colors, consistent rendering under WSLg, and nothing to license or package. |
| D-014 | 2026-10-16 | GUI palette "Tungsten & Amber" (dark only) and layout proportions (tree 14u, properties 17u, viewer stretch) are fixed by the owner; values live in gui/theme.py and change only on his request. | The owner defines the visual identity; implementation must not invent or tune it. |
| D-015 | 2026-10-16 | Main window layout follows the owner's reference: left sidebar (project header, search, sections), stage pill and view pill in strips above/below the viewer, collapsible property cards; pills are not overlaid on the OpenGL viewer. | Overlay widgets over OpenGL are unreliable under WSLg, and strips keep the viewer a plain widget. |
| D-016 | 2026-10-16 | Layout and visual language follow docs/design/design_preview.png (the mockup; supersedes D-015): top bar, tree + properties left, scene tabs + viewer, monitors right, console bottom. Rule: no fake data; every value is real or an explicit empty state, and controls for missing features are omitted or disabled with a phase tooltip. | The owner supplied the target design; the mockup's numbers and labels are placeholders and must never be copied onto the screen. |
| D-017 | 2026-10-16 | Imported surface files are copied into <project dir>/geometry/ and Parts reference them by a path relative to the project file. | Projects stay self-contained and movable; the original file can change or disappear without breaking the project. |
| D-018 | 2026-10-16 | New layer src/vortexcfd/geometry/: numpy and pyvista allowed, no Qt, pyvistaqt or vortexcfd.gui; core must not import it (enforced in tests/test_layers.py). | Surface loading and checks need VTK but must stay usable headlessly from scripts and tests. |
| D-019 | 2026-10-16 | The far-field domain is a box defined by multipliers of the reference length L (largest extent of the union of the parts' bounding boxes); the flow runs along +x and the angle of attack will be set through the inlet velocity direction later. | Multipliers keep the domain valid when parts change size or units; fixing the flow direction keeps patches (inlet at x_min, outlet at x_max) unambiguous. |
| D-020 | 2026-10-16 | Project schema v2 adds `domain`; load_simulation migrates v1 files by adding the default domain, and newer versions are rejected. | Existing projects keep opening while the model grows; the migration hook is the single place that upgrades old files. |
